## Findings addressed

| # | Severity | Finding |
|---|---|---|
| R1 | must-fix | `compose.yml` publishes the metrics/probe ports (`9090:9090`, `9091:9091`) on every host interface, contradicting ADR-014 §4 (and `specs/architecture/observability.md`), which require `expose:` plus a `compose.override.yml` for local development. The surface is unauthenticated by design, so host publication is a real exposure. |
| R2 | should-fix | Ingress `/readyz` can stay `1` after every worker dies while the ingress is idle. `WorkerPool.liveCount()` counts non-null client objects, not reachability, and the idle refresh only ran when `liveCount() == 0`, so a dead-but-connected slot kept the gauge at 1 indefinitely. |

Accepted without change (recorded so they are not re-litigated):

- `src/obs/metrics.zig` (516 lines) and `src/cmd/ingress/http.zig` (1026 lines)
  exceed the 300-line guideline; both are cohesive and pre-existing.
- Histogram `observe()` is not atomic as a group (transient `count ≠ Σ buckets`
  at scrape); harmless for monitoring.
- `renderAll`/`start` exceed 20 lines; single cohesive handlers.
- The 8 KiB `early_stderr` test buffer truncates silently if startup logging
  grows substantially.

## Tasks

1. **R1 — compose port exposure**
   - `compose.yml`: worker metrics `ports:` → `expose: ["9091"]`; ingress
     metrics `ports:` → `expose: ["9090"]`. Keep the API/FKPG ports published
     (`8081:8080`, `8080:8080`) and RabbitMQ unchanged.
   - `compose.override.yml` (new): publish `127.0.0.1:9090` and
     `127.0.0.1:9091` for local development only. Loopback binding keeps the
     override safe even when compose auto-loads it.
   - Regression test: `tests/build/compose_surface_test.zig` asserts
     `compose.yml` contains no host-published `9090`/`9091` mapping and that
     both appear under `expose:`.

2. **R2 — readiness staleness**
   - `src/cmd/ingress/pool.zig`
     - `Slot.last_used_ns: u64` stamped on connect and on every successful
       exchange.
     - `idle_probe_after_ns = 30s` readiness TTL.
     - `refresh(allocator, timeout_ns, stale_after_ns)`: reconnect slots with
       no client **and** drop/reconnect slots whose connection is older than
       the TTL, so a dead-but-connected worker is re-probed.
     - `liveCount()` stays a cheap counter; readiness truthfulness comes from
       `refresh`.
   - `src/cmd/ingress/ingress.zig`: the idle health tick always calls
     `refresh` (not only when `liveCount() == 0`) so a dead seed is
     reconnected and a stale connection is re-probed; publish the returned
     count to `fpkg_ingress_worker_pool_healthy`.
   - `src/cmd/ingress/ingress.zig`: expose `pool` (`pub const pool`) so the
     probe logic is unit-testable, matching the existing `http`/`hmac`/
     `metrics` exports.
   - Regression test: `tests/cmd/pool_test.zig` — a pool connected to a
     listener that then goes away keeps `liveCount() == 1` (the old bug), and
     `refresh` with an expired TTL returns `0`. A second test pins that a
     fresh connection survives a TTL that has not expired.

3. **Docs**
   - `specs/architecture/observability.md`: state the readiness TTL (ingress
     re-probes at most ~30 s of idleness) and keep the `expose:` contract.
   - `specs/decisions/0014-observability-surfaces.md` §5: record the TTL as
     part of the readiness semantics.
   - `specs/quality/verifications/v0.7.1.md`: release checklist.

4. **Release surface**
   - `build.zig.zon` `.version` → `"0.7.1"`. Only the engine version moves;
     `src/clients/browser/package.json` stays `1.0.0-rc.1` (release workflow
     skips npm when the versions differ).
