## M7 review items

- [x] **D1 — ADR-013 adopted; store scope replaced.** The superseded Zig
      `stored`/AOF service is removed from the roadmap and the design specs, and
      ledger idempotency is fixed on the SDK-minted 128-bit `package_id`
      instead of `(fingerprint_id, collection_seq)`. M7 re-dated to Weeks 5–6
      with the cut at v0.6.0. `specs/decisions/0013-event-envelope-ledger-adr.md`.
- [x] **D2 — two-digest reply, append-extend.** `fingerprint_result` v2 appends
      `core_digest[32] + core_feature_count u16 + core_version u16` after the
      unchanged 36-byte v1 prefix (72 bytes total; `payload_len >= 72`). The
      full digest stays byte-identical, so a 1.0 consumer that stops at 36 bytes
      is unaffected. Pinned by a compile-time layout guard, window-resize and
      core-subset property tests, and a golden core digest. The 86-byte figure
      in the earlier specs was arithmetic drift and is corrected to 72.
- [x] **D3 — envelope type and encoder.** `collection_event = 10` is
      outbound-only (no status byte, no engine operation). The ADR-013 JSON
      document is emitted in a frozen key order, lower-hex digests, with
      registry names, risk flags, and a byte-for-byte golden.
- [x] **D4 — ingress context.** `signal_package_context = 11` carries
      `[u16 session_len][session_id][i64 ingress_received_at][body]`. The
      ingress always wraps HTTP POSTs, validates the session id at the boundary
      (1–128 bytes of `[A-Za-z0-9._:-]`, 400 otherwise), allow-lists the header
      in CORS, and opens the first byte per request to disambiguate frame
      types. The worker strips the context and hashes the inner body unchanged;
      direct TCP/loopback frames stay plain with `ingress_received_at = 0`.
      Unit and e2e tests prove the digest is identical with and without a
      session id.
- [x] **D5 — envelope publish.** With `--publish=amqp`, every successful
      collection publishes one `collection_event` frame on
      `result.collection-event` **after** the unchanged reply. The envelope is
      rebuilt from the same package the engine hashed (canonicalized signals,
      v2 digests/counts parsed from the reply, entropy/risk via core). Failed
      collections and non-collection frames emit nothing; build failures (over
      the 64 KiB cap) and publish failures log and drop rather than truncating.
- [x] **W6-D1 — compatibility pinned from both ends.**
      `tests/clients/browser/transport.test.mjs` reads a 72-byte reply through
      the SDK's 36-byte path (same status/digest/counts, core triple never
      exposed, trailing bytes ignored); `tests/worker/collection_event_test.zig`
      pins envelope byte-identity across independent builds, the integrity
      digest, and the SDK-minted `package_id`.
- [x] **W6-D2 — platform ledger contract.** `deploy/ledger/` carries the
      Postgres DDL (`collection_events`, `uuid` PK on `package_id`, btree on
      `fingerprint_id`/`session_id`/timestamps, `jsonb_path_ops` GIN over
      `signals`), the equivalent MongoDB `$jsonSchema` validator with
      unique/partial/wildcard indexes, and ingestion guidance (48-byte FPKG
      header strip, epoch-ms conversion, `ON CONFLICT DO NOTHING` / Mongo
      `11000`, signals privacy). The example envelope
      `tests/fixtures/ledger/collection-event-v2.json` is generated by the
      production encoder through the real worker reply path, so it cannot
      drift; `SNAP_UPDATE=1` regenerates it. The engine gains no database
      dependency.
- [x] **W6-D3 — ingress HMAC + replay window.** Setting `FPKG_HMAC_SECRET`
      (32+ characters, environment only) makes every POST carry
      `x-fpkg-collected-at`, `x-fpkg-nonce`, and
      `x-fpkg-signature: hmac-sha256=<hex>` over
      `fpkg-hmac-v1 / collected_at / nonce / sha256(body)`. Fail-closed:
      missing/malformed/forged/stale (past or future, outside
      `FPKG_HMAC_WINDOW_MS`, default 5 min) → 401; replayed nonce → 409;
      exhausted replay cache → 503. Constant-time compare, a bounded
      65 536-slot cache that compacts and refuses rather than evicting, and
      `FPKG_HMAC_SECRET_PREVIOUS` for rotation sharing one nonce space. Off
      unless configured (D-v1-2); the browser SDK cannot hold a secret, so
      signing is a trusted-edge/platform-gateway job.
- [x] **W6-D4 — security plan refreshed for v0.6.0.**
      `specs/security/SECURITY_PLAN.md` now documents the shipped surface:
      closed H-1 idle timeout, the optional HMAC boundary, the two outbound
      surfaces and what each reveals, boundary caps, the three replay/
      idempotency layers and their owners, ledger PII/at-rest policy, the
      AMQP-credentials-as-CLI-flags gap, and platform-side scope.

## Contract-freeze checks

- [x] **SDK 1.0 surface unchanged.** No public symbol added since the D1 freeze.
      `specs/product/SDK_API_SURFACE.md` still describes the shipped surface;
      the new reply bytes are asserted to stay invisible
      (`coreDigestHex` does not exist), and the type-level suite is unchanged.
- [x] **Wire changes are append-only.** New message types 10 and 11 are
      additions; the reply grows only after the frozen 36-byte prefix; unknown
      trailing bytes are ignored by the SDK. No field was reordered or removed.
- [x] **Engine stays compute-only.** No storage module, no AOF, no database
      client. `deploy/ledger/` is copyable platform-side DDL/validator plus a
      fixture. Worker and ingress remain stateless; request state lives in a
      per-frame arena.
- [x] **No new dependencies.** Zero third-party Zig packages; the SDK still has
      no runtime dependencies.

## Carried forward (not v0.6.0)

- **S5/M8 — DLQ.** Poison frames and failed envelope publishes are log-and-drop.
  Whether the worker owns a bounded DLQ or the platform compensates is an open
  question in the security plan.
- **AMQP credentials** still arrive as CLI flags (`--amqp-user`/`--amqp-password`)
  and `guest/guest` in the dev compose file; move to environment/secret input.
- **Rate limiting and TLS termination** in front of the ingress (H-4/H-5).
- **Replay cache is per-process**; multi-instance ingress accepts that retries
  need new nonces, or pins clients at the proxy.
- **`core_digest` exposure to SDK callers** — deliberately not added; revisit as
  a post-1.0 additive change.
- **M7.1 identity anchoring** — platform-side, fast-follow after v1.0.0.
