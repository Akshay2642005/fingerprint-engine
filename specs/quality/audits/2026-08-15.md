## Headline: the browser SDK and the engine model disagree on the highest-weight features

The four `critical`-weighted features in the model (`CanvasHash` weight 100,
`WebGLHash` 100, `AudioHash` 95, `FontsHash` 95) are declared as
`Bytes` *digests* ("SHA-256 hash of rendered canvas", …) capped at **64 bytes**
in `src/core/normalization/bounds.zig:83`. The default browser collection path
does not produce digests for three of them — it ships raw payloads under the
wrong type and size (BUG-008). Every package from a real browser therefore
trips `type_mismatch` and `bytes_too_long` normalization warnings on the
two/three heaviest signals, inflating server-side risk scores and wasting
~44 KB of payload per POST. The wire-level parity tests
(`tests/clients/browser/package_parity.test.mjs`) prove byte-encoding
correctness but never assert that collected signals conform to the engine's
registry types/bounds — the exact cross-check that would have caught this.

## Confirmed defects

### BUG-008 — Browser SDK emits non-conforming values for CanvasHash / AudioHash / FontsHash (high)

- `FontsHash`: `src/clients/browser/src/collectors/collector.ts:137` pushes
  `{ id: FeatureID.FontsHash, type: FeatureType.StringArray, value: fonts }`
  (the raw font-name list), while `src/model/definitions.zig:61` declares
  `value_type = .Bytes`. `validateTypes`
  (`src/core/normalization/types.zig:28`) flags `type_mismatch` on every
  package, and `risk.zig:82` raises the `type_mismatch` risk flag on a weight-95
  critical feature.
- `CanvasHash`: `collector.ts:102` + `canvas.ts:63-64` ship
  `getImageData(0,0,200,50)` raw pixels (40,000 bytes) under
  `FeatureType.Bytes`. The bound is 64 bytes (`bounds.zig:83`) →
  `bytes_too_long`.
- `AudioHash`: `collector.ts:129` + `audio.ts:74-78` ship 4,096 raw
  `Float32` bytes → `bytes_too_long`.

Resolution options: hash in-browser to the documented 32-byte digest, or add
raw-pixel/raw-waveform feature ids to the model and keep the digest semantics
for the Hash ids. The `Bytes` digest contract matches the model's "SHA-256 hash
of …" descriptions and the 64-byte bound, so hashing in-browser (a digest, not
a fingerprint algorithm) is the smaller change; otherwise the model is wrong.

### BUG-009 — `@enumFromInt` on untrusted wire/JS values (high)

`src/serialization/binary.zig:259` and `:262` build `FeatureType`/`FeatureID`
with `@enumFromInt` directly from untrusted wire bytes. An invalid tag is
undefined behavior; the subsequent `Registry.get(id)` lookup
(`src/model/registry.zig`) indexes a comptime table out of bounds → worker
crash on a malformed frame. The same pattern appears in every
`fingerprint_add_*` export in `src/wasm.zig:83-103` (`@enumFromInt(feature_id)`
from a JS-supplied `u32`), where an out-of-range id becomes a wasm trap and the
computation silently fails. Validating the tag against the registry (or
`std.meta.intToEnum` + a bounds check) before use is required on both paths.

### BUG-010 — Audio fingerprint is non-deterministic (high)

`src/clients/browser/src/collectors/audio.ts:33-67`: a live `AudioContext`
created without a user gesture is **suspended** under Chrome/Safari autoplay
policy, so no audio renders, every bin reads `-Infinity`, and the "fingerprint"
is a constant 4,096-byte blob of `00 00 80 FF` — identical for all users, zero
entropy. When running, the analyser is sampled against 10 ms wall-clock timer
jitter while the FFT window (2048 samples ≈ 46 ms) has not fully rendered, so
the same machine yields different bytes across sessions. Both effects make the
canonical digest unstable for the primary (matching) use case. The documented
deterministic alternative (`OfflineAudioContext`) is broken and dead — BUG-015.

### BUG-011 — `integerScore` can overflow/panic on i64 extremes (medium)

`src/core/similarity/feature.zig:26`: `const diff = @abs(a - b)` on i64.
`a - b` overflows when `a = i64.min, b > 0` (panic in Debug/ReleaseSafe,
wraps in ReleaseFast), and `@abs(i64.min)` is UB. Values come from untrusted
packages (e.g. `collected_at`, `ConnectionRtt`, `InnerWidth`). Guard with
`@abs` on separately-cast u64s or clamp the inputs.

### BUG-012 — Jaccard array similarity can exceed 1.0 (medium)

`src/core/similarity/feature.zig:71-133`: with duplicate elements in the input
arrays (e.g. `a = [X, X]`, `b = [X]`) the per-item intersection count exceeds
the true set intersection, and `union = a.len + b.len - intersection` can make
the score `> 1.0` (here `2/1 = 2.0`). The documented contract is
"0.0 … 1.0". Deduplicate inputs first or clamp the score.

### BUG-013 — `jsonEncode` emits invalid JSON (medium)

`src/serialization/json.zig:52` and `:84` encode `Bytes` values as
`"\xNN"` escapes. `\x` is not a valid JSON escape sequence (RFC 8259 allows
`\uNNNN`, `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`). Any JSON output
containing a `Bytes` feature is unparseable by conforming consumers.

### BUG-014 — The JSON codec is advertised but unusable end-to-end (medium)

`src/engine/engine.zig:38` accepts `req.codec == .json`, but
`src/engine/format.zig:30` returns `InvalidPayload` for json in every op, and
the worker's `codecOf` (`src/cmd/worker/worker.zig:206-210`) passes json
through. There is no `jsonDecode`; `jsonEncode` is encode-only; `codec_test`
does not exercise an op. The dispatch boundary accepts a wire tag that can
never succeed — either implement decode or reject json at the boundary.

### BUG-015 — `collectAudioFingerprintSync` is broken and dead (low)

`src/clients/browser/src/collectors/audio.ts:112-115`:
`OfflineAudioContext.startRendering()` returns a `Promise<AudioBuffer>`; the
code casts it to `AudioBuffer` and calls `getChannelData(0)` on it, which
throws and returns `null` — the function can never succeed. It is also never
called (only `collectAudioFingerprint` is wired in `collector.ts:127`).

### BUG-016 — `CSSCustomProperties` is permanently false (low)

`src/clients/browser/src/collectors/collector.ts:71`:
`CSS.supports("color", "--test: red")` tests `--test: red` as a *value of the
`color` property*, which is invalid everywhere. Custom properties must be
tested as `CSS.supports("--test", "red")` or
`CSS.supports("(--test: red)")`. The signal is constant across browsers.

## Compliance violations (CONVENTIONS.md)

### C-1 — Assertion density far below the mandated minimum (high)

CONVENTIONS.md:113-114 requires an **average of at least two assertions per
function**. The codebase has **183 `assert(` calls across 701 functions**
(0.26/function). `core/` (hashing, normalization, similarity, risk, entropy,
validation), `serialization/`, `engine/`, `cmd/`, `adapter/tcp.zig`,
`adapter/client.zig`, `wasm.zig`, `model/` all contain **zero** assertions.
Only `adapter/amqp/{client,protocol}.zig` (90+44) and `stdx.zig` (19) carry the
weight. The stated guarantee ("assertions downgrade catastrophic correctness
bugs into liveness bugs") is effectively unimplemented on every trust boundary
(frames, requests, hashing invariants, sort order). This is the single largest
gap against the documented standard.

### C-2 — Functions over the 70-line hard limit (medium)

`core/normalization/bounds.zig:103` checkBounds (114),
`adapter/amqp/client.zig:859` process_method (105), `scripts.zig:305`

### C-5 — Magic numbers and non-data-driven bounds (low)

`core/risk/risk.zig` uses unnamed thresholds (0.15/0.4/0.05/0.2/0.5/4.0/0.3);
`core/similarity/feature.zig` hard-codes `INT_MAX_RANGE`/`FLOAT_MAX_RANGE` and

ranges in switch statements rather than deriving them from the metadata
registry (CONVENTIONS "data-driven" + "compile-time-first" design debt). A
comptime pass that every `FeatureID` has declared bounds/type in metadata would
remove the whole switch class.

### C-6 — Spurious error unions on the hot path (low)

`src/engine/engine.zig:41` `process(...) !void` also cannot fail (every failure
is folded into `res.status`), so `try engine.process` in
`src/cmd/worker/worker.zig:228` is dead ceremony. CONVENTIONS:455 "simpler
function signatures".

## Robustness / hardening

- **R-1 (medium)** — `dispatch_table` (`engine/engine.zig:24-42`) has no
  comptime exhaustiveness check over `Operation`; a new operation silently
  becomes `invalid_request`. Add a `comptime` block asserting every
  `Operation` tag has a handler.
- **R-2 (medium)** — `http.zig` reflects the caller-controlled `Origin` header
  into a fixed `[768]u8` response-head buffer (`reply`, `http.zig:567-576`).
  An `Origin` near the 16 KiB `max_header_bytes` cap overflows the buffer →
  `error.NoSpaceLeft` propagates and the connection is dropped without a
  response. Cap/truncate reflected headers or bound `Origin` at parse time.
- **R-3 (medium)** — `serialization/binary.zig:85-86` encodes every feature
  payload into a fixed `[1024]u8` buffer → legitimate values above 1 KiB fail
  with `error.BufferOverflow`. The public API has no absolute size cap
  (decode allocates per wire `u32` lengths; only the adapter's 16 MiB frame cap
  bounds it).
- **R-4 (low)** — `binary.zig:269-271` Boolean decode accepts any non-zero
  byte; declared `payload_len` is never cross-checked against consumed bytes;
  a mid-array decode error leaks already-allocated inner items.
- **R-5 (low)** — `io/frame.zig:66-75` reads the header `reserved` field
  without validating it is 0.
- **R-6 (low)** — `cmd/worker/worker.zig:35,323` caps every reply at 64 KiB
  (`max_result`); `package`/`serialize` results for a full SignalPackage can
  exceed this and fold into `status.buffer_overflow`. Document the cap or grow
  the reply path.
- **R-7 (low)** — `splitHostPort` (`worker.zig:422`, `ingress.zig:176`,
  `pool.zig:105`) uses `lastIndexOfScalar(':')` → IPv6 `[::1]:8080` unsupported
  everywhere.
- **R-8 (low)** — `wasm.zig` shares one `scratch_buffer` across all
  `fingerprint_add_string`/`add_bytes` calls, which store slices into it; a
  second add without an intervening compute aliases/corrupts the first.
  `fingerprint_normalize` returns only a warning count (no per-feature detail);
  `fingerprint_risk` returns `1.0` (max risk) on any error.

H-1/H-2/H-5 from the 2026-08-08 audit are now **done** (per-frame idle
deadlines, graceful shutdown, `--max-body` 413). H-3 is done for the ingress
(`GET /healthz` in `http.zig:356-368`) but the worker Docker image still has no
`HEALTHCHECK`/probe. H-4 (auth, rate limiting, TLS on the public ingress) and
F-4 (AMQP consumer + DLQ) remain open.

## Test coverage gaps

- **No browser collector tests** — canvas, audio, fonts, webgl, battery, media,
  speech, input, permissions, and the `collectSignals` orchestration have zero
  coverage. Every BUG-008/010/015/016 defect ships untested.
- **No cross-layer conformance test** — the exact check
  (`Signal[]` conforms to the engine's registry types/bounds) that would have
  caught BUG-008.
- **No negative-space fuzz/similarity tests** — nothing exercises
  `integerScore` at i64 extremes (BUG-011) or duplicate arrays in Jaccard
  (BUG-012); the three fuzz targets cover decode/hashing/normalize only.
- **No `collect()`/`configure()` integration tests** — unguarded throws
  (`index.ts:47-68` can `ReferenceError` in a Worker context or `RangeError`
  from `BigInt(NaN)`), `configure()` socket leaks on re-call, and the WS
  reconnect budget is never reset after a successful connection
  (`transport.ts:98,123-129`).
- **TS SDK tests never run in CI** (see D-4).

## Ops / process drift

- **D-1 (low)** — `CLAUDE.md:8` says "Zig 0.16.0"; the repo pins and builds
  with **0.14.1** (`build.zig.zon:5`, CI, Dockerfiles, README, docs).
- **D-2 (low)** — `specs/planning/SESSION.yaml:57-59` reports 385/378/7 tests;
  the actual suite is **432/413/19**. This is a recurrence of BUG-003 — the
  fix refreshed the numbers once, and they drifted again. Make CI's
  `zig build test --summary all` the reference and keep spec counts
  best-effort (as BUG-003's own resolution suggested). Also
  `SESSION.yaml:11` says `git.status: clean` while `build` is untracked.
- **D-3 (low)** — stray empty untracked file `build` at the repo root.
- **D-4 (medium)** — CI (`ci.yml`, `release.yml`) is **Linux-only** and never
  runs the browser TS tests (`node --test`) nor `zig build test-integration`.
  BUG-004..007 were all darwin-only panics that Linux CI could not catch; the
  `io` layer is per-OS (epoll/kqueue/IOCP). Add macOS (+Windows) jobs and a
  Node step for `tests/clients/browser`. The release pipeline gates only on the
  Zig unit suite.
- **D-5 (low)** — worker AMQP defaults are `guest/guest` (`worker.zig:72-73`);
  F-4 (AMQP consumer + DLQ) and S5/S6 remain unlanded per
  `SESSION.yaml` handoff.
- **D-6 (low)** — no full-stack `compose.yml` (F-5/S6); `deploy/` has only the
  worker and ingress Dockerfiles; the ingress image has no CI build job.
