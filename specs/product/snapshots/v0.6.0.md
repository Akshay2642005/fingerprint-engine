# Product snapshot — v0.6.0 (2026-10-27)

Current state of the product after the M7 "event envelope + platform ledger
contract" milestone. Refreshed after every release; this file is the "what
exists today" answer to product questions.

## In one sentence

A deterministic, zero-dependency fingerprint computation engine in Zig 0.14.1:
a TypeScript browser SDK collects 102 signals and POSTs a versioned
SignalPackage to an ingress; stateless Zig workers compute the canonical
fingerprint, risk, and entropy; and each successful collection additionally
emits a self-describing JSON `collection_event` envelope that a platform can
persist directly into its own Postgres or MongoDB ledger, with no engine-side
storage and no change to the reply the SDK already receives.

## Wire contract (v1.0-frozen surface)

| Item | Value |
|------|-------|
| FPKG header | 48 bytes, magic `FPKG`, version 1, SHA-256 payload integrity |
| Reply | `fingerprint_result` v2, 72 bytes; 36-byte v1 prefix unchanged; trailing bytes ignored by the SDK |
| New message types | outbound `collection_event = 10`; inbound `signal_package_context = 11` |
| Envelope routing | AMQP exchange `fingerprint`, routing key `result.collection-event`, body = complete FPKG frame |
| Envelope contents | `schema_version`, `package_id`, `session_id`, `fingerprint_id`, `core_digest`, counts, `status`, `entropy`, `risk`, `collected_at`, `ingress_received_at`, `sdk_version`, `signals` |
| Idempotency | SDK-minted 128-bit `package_id` (32 lowercase hex) is the ledger's primary/unique key |
| Timestamps | epoch **milliseconds**; `ingress_received_at = 0` means "not via HTTP ingress" → store `NULL` |
| Ingress auth | optional, `FPKG_HMAC_SECRET`; `x-fpkg-collected-at`, `x-fpkg-nonce`, `x-fpkg-signature: hmac-sha256=<hex>` |

The reply contract did not change: `core_digest` and friends travel on the wire
for the platform but are not exposed to SDK callers in 1.0.

## Testing posture

- `zig build test --summary all` → **549/549** (525 unit + 24 integration).
- `npm run verify` (SDK) → typecheck + type-level surface + **30/30** runtime
  tests.
- Cross-browser matrix: 3 browsers × 3 environments, zero drift against the
  checked-in golden digests; CI fails on any decodable difference.
- Golden fixture `signal-package-v2.bin` pins the canonical digest across Zig,
  worker, and TS tests.
- `tests/fixtures/ledger/collection-event-v2.json` is generated from the
  production encoder through the real worker reply path, so the published
  example cannot drift from the wire bytes.

- GitHub Release: WASM infra artifact + four native tarballs

- GHCR images: `fingerprint-worker` and `fingerprint-ingress`.
- npm: SDK pre-release `1.0.0-rc.1` under `@next`; `latest` remains `0.4.1`
  until the SDK 1.0.0 final. Engine tags do not publish npm.

## Known gaps (tracked, not regressions)

- Poison frames and failed envelope publishes are dropped, not dead-lettered
  (S5/M8).
- AMQP broker credentials are still CLI flags (`ps`-visible); move to
  environment/secret input.
- Rate limiting and TLS termination sit in front of the ingress, not inside it.
- The ingress replay cache is per-process; a retry needs a new nonce.
