# Product snapshot — v0.7.0

Released: 2026-11-11

M8 makes the distributed engine observable and honest under operational
failure without adding a database or changing the frozen collection envelope.

## Shipped

- Prometheus text metrics and `/readyz` on dedicated listeners for ingress and
  worker.
- Request IDs minted or honored by ingress, validated with the existing bounded
  identifier grammar, forwarded in `signal_package_context_v2`, logged by the
  worker, and copied to AMQP headers.
- Mandatory AMQP publishing with nonfatal `basic.return` handling. Unroutable
  events are republished once to `fingerprint.dlx` and counted by outcome.
- Broker transport failures mark the worker unready and cause one reconnect
  attempt before the next collection. The browser reply remains independent of
  AMQP publishing.
- Compose AMQP credentials are supplied by environment variables. Legacy CLI
  credentials remain accepted only as a deprecation path.
- M8 chaos and SLO acceptance record in `specs/quality/m8-slo.md`.

## Verification

- `zig build test --summary all`: 577/577, 551 unit and 26 integration tests.
- `zig build` and `zig build wasm`: green.
- Browser SDK `npm run verify`: 30/30 runtime tests, typecheck and type surface
  green.
- Remote CI is required on the release PR, including the browser matrix,
  worker and ingress builds, Docker builds, and WASM build.

## Explicit boundaries

The engine remains stateless. Event durability, ledger retention, TLS, rate
limiting, authentication and tenancy remain platform responsibilities.
